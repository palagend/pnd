# Palgend（帕兰德）· 个人极简数字工作台

**个人自用 · 移动端优先 · 边缘全栈 · 零运维数字工作台**

基于 Nuxt4 \+ Nitro2 原生边缘全栈开发，主打极简、干净、自用优先，用于解决个人记账、客户管理、项目台账管理等日常效率需求。

本项目以**技术学习为核心、实用落地为目的、佛系迭代为节奏**，非商业项目，拒绝臃肿堆砌，只为自用舒适。

---

## ✨ 核心特点

- **📱 移动端优先**：全站适配手机端，碎片化随时随地操作

- **🎯 极简克制**：功能做减法、体验做加法，只保留刚需功能

- **☁️ 边缘零运维**：依托 Nitro 边缘函数 \+ Vercel 部署，无需自建服务器

- **📶 PWA 离线可用**：添加桌面快捷方式，断网可操作，联网自动同步

## 📁 项目目录结构（Nuxt4 官方标准 · 最终版）

遵循 Nuxt4 强制分层规范，区分客户端/服务端/公共资源，无过度设计、无冗余目录

```bash
palgend/
├── app/                        # Nuxt4 客户端主目录（所有前端代码收拢于此）
│   ├── assets/                 # 全局样式、图标、编译型资源
│   ├── components/             # 全局公共UI组件、业务组件
│   ├── composables/            # 客户端组合式函数、通用hooks
│   ├── layouts/                # 全局页面布局
│   ├── middleware/             # 前端路由守卫、权限拦截
│   ├── pages/                  # 全局页面路由（自动生成路由）
│   ├── plugins/                # 客户端插件注册（Pinia、Vant、PWA等）
│   ├── stores/                 # Pinia 全局状态管理
│   ├── utils/                  # 客户端工具函数（格式化、文件导出等）
│   ├── app.vue                 # 项目根入口
│   ├── app.config.ts           # 客户端运行时配置
│   └── error.vue               # 全局异常兜底页面
│
├── server/                     # Nitro2 边缘服务端根目录（纯服务端逻辑）
│   ├── api/                    # 自动注册 /api/* 业务接口（CRUD核心接口）
│   │   ├── bills/              # 记账模块接口
│   │   ├── clients/            # 客户管理模块接口
│   │   └── projects/           # 项目台账模块接口
│   ├── routes/                 # 无/api前缀全局路由（文件下载、健康检测等）
│   ├── middleware/             # 服务端全局拦截（Token鉴权、CORS、请求校验）
│   ├── plugins/                # 服务端初始化逻辑（数据库连接、环境初始化）
│   ├── db/                     # Drizzle配置、数据表Schema、RLS权限规则
│   └── utils/                  # 服务端通用工具函数
│
├── shared/                     # Nuxt4 专属公共目录（前后端通用资源）
│   ├── types/                  # 全局TS类型定义（前后端共用，统一类型）
│   └── constants/              # 全局业务常量、枚举值
│
├── public/                     # 静态资源（PWA图标、favicon等）
├── docs/                       # 项目全套文档（架构、数据库、部署、规范）
├── scripts/                    # 脚本文件（数据库迁移、批量处理脚本）
├── .trae/                      # 项目编码规范、配置规则
└── nuxt.config.ts              # 项目全局配置文件
    
```

## 📜 项目核心开发原则（长期坚守）

1. **自用优先原则**：功能必须自己先用、验证价值，再迭代优化、对外分享

2. **极简克制原则**：功能做减法，体验做加法，宁可少而精，绝不多而杂

3. **质量优先原则**：无硬性迭代截止日期，优先保证代码质量和使用体验

4. **零运维原则**：全程使用边缘部署，不自建服务器，降低维护成本

5. **移动优先原则**：所有功能优先适配移动端，保证手机端流畅体验

6. **数据自主原则**：所有业务数据支持一键导出，用户完全掌控数据

7. **技术务实原则**：以学习落地为目的，不追新技术、不堆砌技术栈

8. **佛系变现原则**：不刻意盈利，收益仅作为额外惊喜

9. **持续沉淀原则**：记录开发过程，沉淀技术经验，持续优化项目

10. **灵活迭代原则**：根据自用场景灵活调整功能，不固化设计

## 🚀 快速开始

### 环境依赖

- Node\.js \>= 24\.x

- pnpm 包管理器

### 本地开发启动

```bash
# 安装依赖
pnpm install

# 启动本地开发服务（支持前后端热更新）
pnpm dev

```

访问地址：[http://localhost:](http://localhost:3000)5173

### 项目构建打包

```bash
# 生产环境构建
pnpm build

# 预览生产构建产物
pnpm preview

```
